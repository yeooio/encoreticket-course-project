# 用户昵称必须由用户确认后保存

状态：accepted

## 背景

注册和资料修改需要一个清晰的昵称输入流程。服务端自动保存随机昵称会让用户在未确认的情况下产生资料变化，也不利于注册页和资料页复用同一套交互。

## 决策

- 注册请求必须携带昵称，昵称长度为 1–64 个字符。
- `PATCH /users/me` 可以只修改头像；如果携带昵称，昵称必须是非空的 1–64 个字符。
- `GET /users/nickname/suggestion` 对游客公开，每次返回一个随机昵称候选。
- 随机昵称候选接口不写入数据库；只有注册或资料更新请求提交后才保存昵称。
- 随机候选由服务端生成，客户端不能决定或伪造服务端生成规则。

## 影响

- 注册页面需要在提交前拥有一个最终昵称，可以由用户输入或使用随机候选。
- 随机候选接口可以被注册页和当前用户资料页复用。
- 不需要新增数据库字段、唯一约束或登录态变更。
