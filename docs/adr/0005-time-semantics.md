# 技术时间用 Instant，业务时间用 LocalDateTime

状态：accepted

## 背景

`docs/api/common-contract.md` 要求技术时间按 UTC 计算和保存、接口返回带偏移量的时间，同时要求场次时间按影城时区解释。两种时间如果共用同一种类型，会产生两个后果：一是连接层会把业务时间也做一次时区换算，二是"哪个时区的 20:00"这个语义无处表达。

## 决策

- 技术时间（电影 `publishAt`、创建、更新、订单过期、支付通知、核销）使用 `Instant`，按 UTC 计算与保存。`publishAt` 表示一个绝对时刻，不属于某个影院的墙面时间；接口返回等价的带偏移量 RFC 3339 时间，V1 管理端按 `Asia/Shanghai` 展示。
- 业务时间（场次开始与结束、售票起止）使用 `LocalDateTime`，表示影城的墙面时间；接口输出必须拼上影城时区偏移（V1 为 `Asia/Shanghai`），不裸输出无偏移的时间。
- JDBC 连接时区固定为 `UTC`，使 `Instant` 的时间点换算只发生在连接层一次；技术时间使用的 `DATETIME` 列按 UTC 写入。场次等业务时间的 `DATETIME` 列配合 `LocalDateTime` 使用，不触发时区换算，保证业务时间字面量稳定。
- 时间展示时区由接口契约或影城配置决定：前端拿到带偏移量的时间后按用户本地时区渲染，后端不把部署机器时区当作业务时区。

## 影响

- 技术时间的 `DATETIME` 值按 UTC 解释；改变 JDBC 连接时区等于改变历史数据语义，需要重建或迁移存量数据。
- 将来支持多影城时，影城表增加时区字段，业务时间按该影城时区输出，不再硬编码 `+08:00`。
