# V1 业务范围与支付边界

状态：accepted

V1 面向单影院、固定票价的购票场景，退款只支持整单退款，支付使用模拟渠道。这样先固定订单、座位、票券和退款的核心业务边界，优惠定价、多影院组织模型、部分退款和真实支付渠道留到后续版本；这些能力变更时需要重新评估数据模型和接口契约。

## Consequences

- 当前不需要影院/门店组织实体，也不需要按影院划分数据范围。
- 订单明细必须保存购票时的价格快照，但暂不需要优惠或价格规则表。
- 退款申请以订单为单位，不能只退订单中的一张票。
- 模拟支付仍需覆盖成功、明确失败、重复通知和迟到通知，便于验证订单状态与座位释放规则。
